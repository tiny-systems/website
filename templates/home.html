FOR YOUR TEAMthe loop: issue in · PR out

Label an issue. Harvest a pull request.

1

Sow

File a GitHub issue and add the tiny label. That is the entire ceremony — anyone on the team, straight from the GitHub UI.

2

Deliver

A five-second Actions job on the in-cluster runner drops the issue into the root session's inbox. Event-driven; nothing polls, nothing waits around.

3

Grow

The root session plans, spawns specialists in the right toolchains, and raises a ✳ only when a decision is truly yours. Overnight is fine — sessions survive everything, including us killing their pods on purpose.

4

Harvest

Agents hold zero credentials. Finished branches leave as git bundles through the outbox; a short-lived courier token opens the pull request and comments back on your issue.

THE ENTIRE INTEGRATION.github/workflows/tiny.yml
on:
issues: { types: [labeled] }
jobs:
deliver:
if: github.event.label.name == 'tiny'
runs-on: [self-hosted, tiny]
steps:
- run: |
printf 'issue #%s: %s\n\n%s' "$N" "$TITLE" "$BODY" \
| tiny deliver root --ensure --repo "https://github.com/$REPO.git"
the task hand-off is a prompt piped into tiny deliver — full workflow in the docs

OPTIONSthe machinery under both
--the-real-thing
Attach into the genuine Claude Code CLI over a TTY — every hotkey, plan mode, skills, your .mcp.json. tiny wraps nothing; new features just appear.
--survives-anything
Workspace on a volume, pod disposable. Kubernetes itself resurrects the dead; the replacement resumes the transcript mid-thought.
--image any:tag
golang:1.26, buildah, your dev image — the agent injects itself into whatever you name. Nothing to bake, nothing to maintain.
--humans-hold-the-gate
Dangerous moves park as Question objects until you answer. Your y both approves and performs — audited as you, not a service account.
--no-credentials
No deploy keys, no PATs, nothing stored in pods. Work leaves through the outbox; a compromised agent can neither push nor call GitHub.
--no-control-plane
No operator, no server, no manager pod — the CLI and Kubernetes itself do everything. Only the sessions you run and the add-ons you switched on ever occupy the namespace.
--tmux-native
Every session lives in tmux. Attaching is a real tmux attach — panes, scrollback, your muscle memory — and detaching never stops the work.
--resources cpu,mem
Per-session requests and limits, straight from the session spec. The fleet screen shows live CPU and memory next to every name.
--drop-a-file
Drag a file onto a session’s row in the fleet screen and it lands in that workspace. No kubectl cp, no scp gymnastics.
--agent claude|codex
Two agents, one runtime. Claude Code by default; --agent codex runs OpenAI’s Codex — same fleet screen, same gate, same resume.
--model your-pick
Pin the model per session — claude --model / codex -m underneath. Also a field on the options form.
--broadcast
One message into every unfinished session’s inbox: [b] on the fleet screen, tiny broadcast for cron and CI.

[✓] registry-cacheZOT

Pull-through image cache inside your namespace. golang:1.26 downloads once per cluster, not once per session — and docker.io rate limits stop being your problem. An optional DaemonSet teaches every node to trust it.

[✓] artifact-storeMINIO

S3-compatible store beside the sessions. Things too big for git — builds, screenshots, datasets — land here instead of dying with a pod.
