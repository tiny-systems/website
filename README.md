# tinysystems.io and tinysystems.dev

Two websites from one repo. Static files, generated by a small Go program,
served by one nginx image that picks the site by host.

- **tinysystems.io**: the Tiny Systems app, for people who aren't developers.
  `templates/apphome.html`, with the app's web build in `static/app-demo/`.
- **tinysystems.dev**: tiny, the engine: docs, comparisons, the engineering
  blog. `templates/home.html`, `pages.html`, `layout.html`.

Files:

- `main.go`: the generator: `content/` + `templates/` + `static/` → `dist/io/` and `dist/dev/`
- `content/docs/*.md`: the manual (front matter: title, description, section, weight)
- `content/blog/*.md`: field notes (front matter: title, description, date, author)
- `content/compare/*.md`: comparison pages
- `templates/`: Go html/template layouts. `{{base}}` is the site being built,
  `{{appsite}}` and `{{devsite}}` link across.
- `nginx.conf` + `common.inc` + `redirects.inc`: serving config. The app host
  301s `/docs/`, `/blog/`, `/compare/` and `/tiny/` to the same path on
  tinysystems.dev, which moved there on 2026-11-27.

Build and preview locally:

```
go run .
python3 -m http.server 8099 -d dist/io    # the app site
python3 -m http.server 8098 -d dist/dev   # tiny's site
```

Refresh the embedded app after changing its frontend: `scripts/web-demo.sh`
in the app repo.

CI builds `ghcr.io/tiny-systems/website` on every push to main; flux deploys it.
